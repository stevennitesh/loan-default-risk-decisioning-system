## Git inclusion rule

Git excludes report files by default. The explicit final-file exceptions in
[.gitignore](../.gitignore) admit the reviewed historical reports and the named
correctness/tuning evidence below. Keep source, tests, configuration, dependency
locks, documentation, final report visuals, and anonymous aggregate results in
Git. The curated Power BI reports and screenshots remain presentation assets;
their historical status is documented in [the Power BI guide](../powerbi/README.md).

Keep downloaded raw data, Parquet/marts/databases, fitted models, per-applicant
scores, exact split memberships, intermediate search outputs, environments,
logs, and scratch/source archives local. The entire `data/` tree is ignored
apart from `.gitkeep` placeholders, including newly introduced subdirectories.
Runtime result files belong under ignored generated scopes even when their
names are new. A final report may summarize a completed run without including
its underlying applicant records.

To promote new final evidence, review its contents, remove source rows and
applicant memberships, document the identified completed run and limitations,
and add only the intended final files to the explicit ignore-rule exceptions.
A filename or being generated by a successful run alone does not make an output
final. Do not force-add runtime files or entire generated directories.

The five named final evidence scopes `correctness_20261004/`, `tuning_20261004/`, `class_weighting_20261004/`, `model_inputs_20261004/` and `portfolio/` preserve literal artifact bytes through the scoped `-text` rules in [`.gitattributes`](../.gitattributes). Their provenance and publication validators compare SHA-256 hashes of file bytes. Git must retain those bytes when staging and checking out CSV, JSON, Markdown and SVG files, regardless of the host or `core.autocrlf` setting. Existing CRLF snapshots remain valid; do not normalize frozen evidence or rewrite scientific execution fingerprints to accommodate a checkout.

This policy covers only those five named bundles. Historical experiment reports, other reports and source files retain their existing text policy, and `.gitignore` still admits only exact reviewed final files. Adding or refreshing a final bundle requires byte checks against the staged blobs and a clean checkout before release; local filesystem hashes alone do not establish published-byte parity. Presentation renderer hashes describe the actual rendering source separately from immutable scientific provenance.

## Curated Evidence

The committed experiment reports and selected CSV snapshots preserve the post-v1 modeling trail used by the README and Power BI comparison. These files are intentionally versioned:

- `reports/experiments/*.md`
- `reports/experiments/experiment_log.csv`
- `reports/experiments/*_selected_features.csv`
- named experiment summary CSVs such as `010_recency_stability_summary.csv`, `012_last_k_stability_summary.csv`, and `014_feature_cleanup_stability_summary.csv`
- calibration, feature-selection, and model-stability comparison CSVs referenced by experiment reports
- `reports/model_card.md`

These artifacts should change only when the corresponding experiment result is intentionally refreshed and the linked narrative is updated in the same change.

These are historical exploratory snapshots, not a validation sign-off. Numbered reports retain their original conclusions and next actions as history. Rows `000` and `015` in `experiment_log.csv` supply the curated v1/post-v1 comparison; earlier rows describe intermediate runs. Interpret them with [current evidence status](../docs/validation/VALIDATION_PLAN.md#current-evidence-status), especially the reused assessment population, SHAP selection, calibration, feature semantics, and policy limitations.

"Frozen" means the snapshot is preserved, not that it is an untouched test set or an exactly reproducible release. PR-AUC means average precision; recall-at-capacity means highest-score capture; expected-value fields use utility units. Preserve numeric evidence when correcting its interpretation. A new corrected evaluation should identify its protocol and artifacts separately rather than rewrite the historical experiment trail.

## Regenerated Runtime Outputs

Standard pipeline outputs such as `model_metrics_summary.csv`, `model_threshold_metrics.csv`, dashboard CSV bundles, figures, and DuckDB/model artifacts are generated locally and ignored by Git. Rebuild them with the Makefile targets documented in the [run guide](../docs/RUNNING.md).

Nested assessment creates a unique ignored directory under
`<report_dir>/nested_assessment/<run_id>/`, with exact local role IDs and seeds,
fold-selected artifacts, outer predictions, selection/ranking diagnostics, and
assessment metrics. Only runs whose manifest says `complete` represent a finished
assessment. These evaluate the declared selection procedure, separately from the
saved dashboard model. See the [methodology explanation](../docs/validation/ASSESSMENT_METHODOLOGY.md).

Scoped runtime reports live under `reports/v1/` and `reports/post_v1/`; the base config has separate default paths. Generated validation/business-value prose describes the implemented legacy calculations and may retain labels qualified by the current validation owner. Do not treat generated wording as an override of those limitations. Dashboard export can recompute calibrated probability-quality and segment tables, so raw runtime metrics and dashboard metrics are different views.

Power BI files and screenshots under [`powerbi/archive/`](../powerbi/archive/README.md) are clearly labeled historical snapshots. Opening them does not require retraining. Their schemas/pages are tested, but visual reconciliation to a newly generated bundle requires a deliberate refresh and inspection. See [the Power BI guide](../powerbi/README.md).

## Named frozen-model input evidence

`reports/model_inputs_20261004/` contains five reviewed anonymous final files for all five current frozen history models: per-fold and mean contribution magnitudes, a raw-input/source-group dictionary, methods and provenance. Each model uses a predeclared target-blind uniform sample of 1,000 assessment applicants, seed 20261004, and its saved fitting-only preprocessing. Absolute native TreeSHAP encoded effects sum by raw field and group before equal five-fold averaging, in raw-margin natural-log-odds units. Signed intercept-inclusive additivity checks stay separate. Group size and correlated/derived inputs limit interpretation; these are model-behavior descriptions, not predictive-value shares, causality or adverse-action reasons. No memberships, individual scores or SHAP arrays are published. Scientific execution fingerprints are preserved.

The offline report copies these final anonymous tables alongside eight embedded charts. `make portfolio-site` verifies hashes and an exact reviewed-file allowlist, then stages only this presentation for the dedicated GitHub Pages workflow. The repository, raw data, models and scratch trees are not the publication artifact. PNG/SVG/CSV downloads are adjacent; online source links point to GitHub. Publication is confirmed separately from local preparation.
